Kolmaf-AI

An experimental desktop layer for connecting LLM reasoning to KoLmafia without pretending the model is the game client. The model can inspect context, reason, explain, and propose; KoLmafia remains the runtime that actually knows the player state and talks to the game.

What is it?

Think of Kolmaf-AI as a control desk between a person, an LLM, and KoLmafia — with the important parts kept visibly separate.

The short version

LLM intelligence, KoLmafia runtime truth.

Kolmaf-AI gives an AI model structured ways to understand the local KoLmafia environment, retrieve scripting knowledge, inspect relevant documentation, and prepare actions for review.

The design goal is not “let the AI loose.” The goal is to make an assistant useful while keeping mutation authority, confirmation, and verification outside the model's own confidence.

Current boundary

Linux first.

The current public desktop line is Linux-only. Windows and macOS are planned targets after the Linux runtime, packaging, and safety flow are stable enough to port deliberately.

Model reality

LLMs can and will make mistakes. They can misunderstand state, invent details, use stale knowledge, or propose the wrong command. Kolmaf-AI is being built around that assumption rather than around the hope that a model will always behave correctly.

How it ties together

The model is one component in a longer runtime path. Context and knowledge tools feed reasoning; explicit gates decide whether a state-changing request can move forward.

What the LLM is for

  • turning a human goal into a concrete plan;
  • reading structured KoLmafia references and local docs;
  • explaining state and surfacing uncertainty;
  • drafting a bounded action proposal instead of silently executing it;
  • helping debug and document the local system.

What KoLmafia is for

  • being the actual game-aware local runtime;
  • providing ASH, gCLI, relay, preferences, session evidence, and live state;
  • performing approved game interactions through the intended local path;
  • giving the desktop a source of runtime truth to verify against.

Platform plan

One runtime at a time. Linux is the proving ground; cross-platform support comes after the core contracts stop moving underneath it.

Before using an LLM near your character

Treat mistakes as expected.

Use at your own risk
Back up first

Make a complete backup of your KoLmafia home before experimenting. Keep a copy you can restore without depending on the AI or the current install.

Minimize exposed Meat

Before testing mutating features, consider moving most of your readily spendable Meat into your closet and keeping only the minimum you actually need available.

Read the proposal

Do not treat a polished explanation as proof that the action is correct. Verify location, target, quantity, cost, and state assumptions.

Prefer reversible tests

Start with low-cost, easy-to-check actions. Build confidence from observed behavior rather than from model certainty.

Keep secrets out of prompts

Do not paste passwords, relay hashes, API keys, session cookies, or other credentials into model conversations or public bug reports.

Verify after mutation

A successful tool return is not the same thing as the intended game state. Read back the resulting state independently.

Plugin showcase

Two KoLmafia-side projects make the model much less dependent on raw guessing: one tells it where things live, and one gives it a structured knowledge plane.

Plugin 01 / navigation + docs

kol-goblin-docs

An agent-first map of the local KoLmafia tree, presented as editable HTML5 documentation. It gives both humans and agents a top-level starting point, branch-by-branch context, runtime snapshots, and a low-friction relay editor.

role
authority
surface

Navigation / context.
It helps the model find and understand the right local area, but a README does not grant permission to execute anything.

Use it when the hard part is “where should the agent look, what is this part of KoLmafia for, and what should it verify before acting?”

Plugin 02 / retrieval + knowledge plane

kol-html-matrix

A local-first KoLmafia scripting matrix with a human relay interface and a machine-readable agent plane. It exposes structured nodes, workflows, use cases, provenance, stable IDs, and mem:// references so the model can retrieve instead of free-associate.

role
authority
surface

Reference / retrieval.
It can tell the model what is relevant and where the evidence came from; it is not an execution authority.

Use it when the hard part is “which KoLmafia concept, command, workflow, or source should ground this reasoning?”

Discussion is part of the build

Questions, testing, pushback, patches — welcome.

If you use KoLmafia and think the model boundary is wrong, a tool contract is confusing, the Linux setup is too brittle, or a plugin should expose better evidence, say so. Useful criticism is part of making an AI integration safer and less annoying.
