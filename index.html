Kolmaf-AI

An experimental desktop layer for connecting LLM reasoning to KoLmafia without pretending the model is the game client. The model can inspect context, reason, explain, and propose; KoLmafia remains the runtime that actually knows the player state and talks to the game.

What is it?

Think of Kolmaf-AI as a control desk between a person, an LLM, and KoLmafia — with the important parts kept visibly separate.

The short version

LLM intelligence, KoLmafia runtime truth.

Kolmaf-AI gives an AI model structured ways to understand the local KoLmafia environment, retrieve scripting knowledge, inspect relevant documentation, and prepare actions for review.

The design goal is not “let the AI loose.” The goal is to make an assistant useful while keeping mutation authority, confirmation, and verification outside the model's own confidence.

Current boundary

Linux first.

The current public desktop line is Linux-only. Windows and macOS are planned targets after the Linux runtime, packaging, and safety flow are stable enough to port deliberately.

Model reality

LLMs can and will make mistakes. They can misunderstand state, invent details, use stale knowledge, or propose the wrong command. Kolmaf-AI is being built around that assumption rather than around the hope that a model will always behave correctly.

How it ties together

The model is one component in a longer runtime path. Context and knowledge tools feed reasoning; explicit gates decide whether a state-changing request can move forward.

What the LLM is for

  • turning a human goal into a concrete plan;
  • reading structured KoLmafia references and local docs;
  • explaining state and surfacing uncertainty;
  • drafting a bounded action proposal instead of silently executing it;
  • helping debug and document the local system.

What KoLmafia is for

  • being the actual game-aware local runtime;
  • providing ASH, gCLI, relay, preferences, session evidence, and live state;
  • performing approved game interactions through the intended local path;
  • giving the desktop a source of runtime truth to verify against.

Platform plan

One runtime at a time. Linux is the proving ground; cross-platform support comes after the core contracts stop moving underneath it.

Before using an LLM near your character

Treat mistakes as expected.

Use at your own risk
Back up first

Make a complete backup of your KoLmafia home before experimenting. Keep a copy you can restore without depending on the AI or the current install.

Minimize exposed Meat

Before testing mutating features, consider moving most of your readily spendable Meat into your closet and keeping only the minimum you actually need available.

Read the proposal

Do not treat a polished explanation as proof that the action is correct. Verify location, target, quantity, cost, and state assumptions.

Prefer reversible tests

Start with low-cost, easy-to-check actions. Build confidence from observed behavior rather than from model certainty.

Keep secrets out of prompts

Do not paste passwords, relay hashes, API keys, session cookies, or other credentials into model conversations or public bug reports.

Verify after mutation

A successful tool return is not the same thing as the intended game state. Read back the resulting state independently.

Tool constellation

Eight companion projects give Kolmaf-AI safer places to test, retrieve, remember, parse, document, and package task guidance instead of asking one model prompt to do everything.

How the tools tie in

Different jobs, different trust boundaries.

sandbox → test away from live state  ·  tokens → typed game data  ·  goblin docs → find the local area  ·  html matrix → retrieve grounded references  ·  memory → carry structured context  ·  skills → inject task guidance  ·  ash-it-down → bounded docs/evidence  ·  kingdomsitter → parse / type / bridge ASH  ·  desktop → proposal + policy gate  ·  KoLmafia → runtime truth

evidence ≠ authority prompt ≠ permission mock ≠ live fallback LLM output = proposal material
Tool 01 / isolated testing

kol-agent-sandbox

Builds a mirrored agent test environment around a pinned loathers/kolmafia-mock, with code-oriented live directories mirrored read-only and agent edits kept in a separate work area.

role
boundary
ties in

Safe proving ground.
It deliberately excludes settings, sessions, cookies, password hashes, and login material. A mock failure never authorizes falling through to live KoLmafia.

Use it to exercise agent changes and compatibility behavior before anything touches the real runtime.

Tool 02 / typed game data

tokens-of-loathing

A fork/compatibility line of data-of-loathing: typed Kingdom of Loathing game data served through SQLite, with an Express transport, TypeScript client, MCP surface, and a compatibility bridge used by the agent sandbox.

role
boundary
ties in

Queryable facts.
It gives tools a structured data source and supplies the verified SQLite compatibility layer that materializes the pinned KoLmafia mock used by the sandbox.

Use it when the model needs typed game-data retrieval rather than prose recollection.

Open tokens-of-loathing on GitHub ↗
Tool 03 / local memory

kol-agent-memory

Creates a KoLmafia-local, cross-indexed memory tree for humans and coding agents, with distinct SYSTEM, STATE, LOCAL, and ROUTING planes plus vector, graph, and Q-table indexes.

role
authority
surface

Context that survives.
Its routing indexes help find memory; they do not become authority over live game state.

The relay stays conservative and does not send chat, kmail, trade, combat, or arbitrary game commands.

Open kol-agent-memory on GitHub ↗
Tool 04 / skill bus

kolmafia-skills

A KoLmafia-native agent skill bus built around a spaceless /skill@... gCLI namespace. Skills live in native aliases and can be listed, synchronized, created, and invoked through the relay.

role
authority
surface

Task guidance injection.
The Python bridge remains read-only. Skill prompts are guidance, not execution authorization.

A safe bare /skill dead-end is installed so accidental input does not fall through to KoLmafia's chat slash-command path.

Open kolmafia-skills on GitHub ↗
Tool 05 / documents + evidence

kol-ash-it-down

A local-first KoLmafia relay/document bridge for bounded text editing, cross-format conversion, gCLI correlation markers, session-tail evidence, status artifacts, and local SQLite audit memory.

role
authority
surface

Files and evidence.
The Python/Conda service is deliberately not a second KoL executor. Writes are previewed, backed up, path-guarded, atomic, and logged.

Use it when an agent needs to work on local artifacts or prove that a bridge path ran without turning that helper into a hidden game-action path.

Open kol-ash-it-down on GitHub ↗
Tool 06 / navigation + docs

kol-goblin-docs

An agent-first map of the local KoLmafia tree, presented as editable HTML5 documentation. It gives both humans and agents a top-level starting point, branch-by-branch context, runtime snapshots, and a low-friction relay editor.

role
authority
surface

Navigation / context.
It helps the model find and understand the right local area, but a README does not grant permission to execute anything.

Use it when the hard part is “where should the agent look, what is this part of KoLmafia for, and what should it verify before acting?”

Open kol-goblin-docs on GitHub ↗
Tool 07 / retrieval + knowledge plane

kol-html-matrix

A local-first KoLmafia scripting matrix with a human relay interface and a machine-readable agent plane. It exposes structured nodes, workflows, use cases, provenance, stable IDs, and mem:// references so the model can retrieve instead of free-associate.

role
authority
surface

Reference / retrieval.
It can tell the model what is relevant and where the evidence came from; it is not an execution authority.

Use it when the hard part is “which KoLmafia concept, command, workflow, or source should ground this reasoning?”

Open kol-html-matrix on GitHub ↗
Tool 08 / ASH language bridge

kingdomsitter

A Go-powered Tree-sitter sidecar for KoLmafia ASH. It parses ASH into a stable typed IR, exposes agent-readable analysis, and emits TypeScript aimed at the KoLmafia / Libram ecosystem without making the model the game runtime.

role
authority
surface

Language / tooling bridge.
Tree-sitter handles syntax while Go owns the IR, analysis, transpilation, and sidecar surface. KoLmafia remains authoritative for real game state and real mutations.

Use it when an agent needs structured ASH understanding, safer refactoring or migration, or an ASH → TypeScript / Libram path instead of treating scripts as unstructured text.

Open kingdomsitter on GitHub ↗
Tool 09 / actor control plane

actor-engine

A Go + ASH actor-driven state plane for monitoring KoLmafia, Kingdomsitter, and KoLmafia releases while exposing one bounded protocol to Go, Rust, Kotlin, C#, C++, C, and Swift clients.

role
authority
surface

Actor / state control plane.
Runtime evidence can activate several states at once, but evidence does not grant authority. The only implemented write in v0.1.0 is exact-state-digest-confirmed local release staging; arbitrary ASH/gCLI execution, release install, restart, and live game mutation are not implemented.

Use it when an agent needs a durable state machine around KoLmafia observations, release monitoring, proposal binding, receipts, and language-neutral actor clients without turning those clients into separate authority domains.
