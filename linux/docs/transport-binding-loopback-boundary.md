# Transport binding and loopback boundary (P1-A/P1-B)

- T2 proposals bind an exact transport identity: writer kind (`kind`), canonical URL (`scheme, host, port, path_class, method`), `opener_class`, and normalized live-enable `environment_flag`, canonicalized (lowercase host, trailing dot stripped, userinfo rejected, explicit or scheme-default port) and fingerprinted as sha256 of the canonical field dict. The opener class distinguishes the uniform no-redirect opener from an injected (test/fake) opener, and the environment flag records live-enable drift. Changing any bound field changes the proposal binding and invalidates prior confirmations.
- Confirmation is bound to that proposal's transport fingerprint. The same high-level command with a different transport must not validate.
- Execution revalidates: the writer's actual transport identity fingerprint must equal the approved fingerprint, checked before confirmation consumption and before any network I/O. Mismatch fails closed with `TRANSPORT_IDENTITY_MISMATCH` and zero network calls. A mutable config cannot substitute a different transport post-approval (RelayWriter re-resolves settings-driven destination per call when not explicitly constructed, so drift is detected).
- Credential-bearing RelayWriter mutations are loopback-only. The destination is parsed with `urllib` (not string matching). Accepted set is exactly `{127.0.0.1, localhost}` on scheme `{http}`; `::1` is rejected (`NON_LOOPBACK_RELAY_REJECTED`), as are LAN/RFC1918, `0.0.0.0`, public IPs, arbitrary hostnames, userinfo, `localhost.evil.*`, encoded/exotic IP forms (`127.1`, `2130706433`, `0x7f000001`, `0177.0.0.1`, `[::1]`, `[::ffff:127.0.0.1]`), missing host, unsupported scheme, and scheme-relative URLs. Ambiguous/malformed destinations fail closed.
- Redirects are disabled for credential-bearing mutations (default opener uses a no-redirect handler); any redirect response fails closed with `REDIRECT_DESTINATION_REJECTED`.
- Failure classes (all before transmission, all zero network): `TRANSPORT_IDENTITY_MISMATCH`, `NON_LOOPBACK_RELAY_REJECTED`, `INVALID_RELAY_URL`, `UNAPPROVED_TRANSPORT`, `REDIRECT_DESTINATION_REJECTED`.
- Writer kinds are typed and non-interchangeable: RelayWriter (`relay-writer`), dry-run (`gcli-dry-run`), fake/test, future native bridge. A fake writer never satisfies a live approval and vice versa; mock failure never falls back to live; dry-run/test/MCP surfaces explicitly inject `DryRunGcliWriter` and never infer a live writer from env.
- Blocked attempts emit a secret-free evidence event (operation id, approved/actual fingerprints, classification); credentials, passwords, and cookies are never logged or persisted.
- T3 denials remain singular and independent of confirmation/transport/writer.
- Code remains authoritative. This note describes the implemented boundary; it is not a claim of universal safety, and it does not resolve equipment/commissioning uncertainty (for example, `can_equip true` does not guarantee a future equip succeeds).
